## Data structures
### Queues has a property of FIFO, first in first out. Meaning that the first data enters the structure should be the first that leaves as they lasted the longer. Enqueue means to get in to the start of the line, and dequeue means to get out from the last of the line. We can impelment this in a simple way by declaring a data struct with a list and a integar tracker of current size, however the list itself needs a predeclared number as its maximum size, this means that the queues itself cannot grow with the data amount. We also need to track the which position is the current last data at to be push out next in the queue for the FIFO feature by adding data to start of array and taking from current last position. Which ensure in the case of data being taking out and putting back to the queue, all data will have been selected once before having the first repeated one.
### Stacks has a property of LIFO, last in first out. Meaning that the last data enters the structure should be the first that leaves just like how the newest emails/clothes/food trays stays on the top although this means older ones often never gets picked up because the newer ones keep getting replenished. Push means to push a data to the top stack, and pop means to take data out from the top stack. We can impelment this in a simple way just as how we implemented queues, we also use the data struct of list and a integar track of where the last data is in, so to be taken out and then a new data can replace that position later whereas the first data went initially stays.

## Reallocation
### When we use malloc to return an address to a pointer with a fixed size of memory in byte, we may need to resize it, larger for more data or less to save memory. To do this we need reallocate the memory, the process is to reuse malloc on a new pointer for a different size then to copying everything from old to new pointer using a for loop, then to free the old pointer memory by free(), we could then make old pointer equal to new, as so reference to any one of them lead to the same address and so we effectively reused the pointer. The reason why we need an extra pointer is that malloc may fail to return a piece of memory and returns NULL, which means we will lost the track of the address to old piece of memory before resizing it, we need to detect the NULL, free the old pointer then to close the program by a return. 
### We can use the realloc() function from stdlib.h to automatically run the copy and paste process, by typing (new pointer) = realloc((original pointer),(new size in byte)), though we still need to detect whether it instead returned NULL and at the end free() the old pointer cause we now have a new pointer with same content but more available spaces.
